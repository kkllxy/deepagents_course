# 15｜部署与成本控制

## 本讲目标

从 demo 到长期使用，需要队列、沙箱池、预算和失败恢复。

## 核心内容

- 本地 CLI 适合第一阶段，内部服务适合团队共享，CI 适合 PR 分析。
- 成本来自 token、子 Agent、工具查询、sandbox、存储和后端压力。
- 控制手段包括最大步数、工具返回限制、子 Agent 限制、缓存、大结果落盘。


## 示例 / 模板

```text
API Server
  -> Job Queue
  -> Agent Worker
  -> Sandbox Pool
  -> Tool Gateway
  -> Evidence Store
  -> Report Store
```

## 工程注意点

- 不要只追求 demo 跑通，要关注权限、证据、失败处理和可复盘。
- 所有真实日志、数据库、shell 命令都应先通过 mock 或 sandbox 验证。
- 输出尽量结构化，方便 Codex 后续读取和整理。

## 面试回答

> 生产化重点不是 create_deep_agent，而是异步任务、沙箱、权限、trace、eval、超时、预算和失败恢复。

## 本讲练习

把本讲能力应用到“排查记录核实 Agent”里，写出你会暴露给 Agent 的工具、路径权限和输出字段。
