# 18｜DeepAgents 面试题速查

## 1. DeepAgents 是什么？

DeepAgents 是一个面向复杂长任务的 agent harness。它不是模型，而是基于 LangChain/LangGraph 的封装，提供计划、文件系统、上下文管理、subagent、memory、sandbox 等默认能力。

## 2. 和 LangGraph 的区别？

LangGraph 是底层图运行时，适合自定义状态机和复杂工作流。DeepAgents 是上层 opinionated harness，适合快速构建开放式长任务 Agent。

## 3. 和 LangChain 普通 Agent 的区别？

普通 Agent 更轻，适合短任务和简单工具调用。DeepAgents 更适合长任务，内置文件系统、todo、subagent、上下文压缩和 memory。

## 4. Backend 是什么？

Backend 控制 Agent 的文件和状态存储，也影响 memory 和 sandbox 能力。不同 backend 对应不同持久化、隔离和权限策略。

## 5. 为什么需要 Sandbox？

因为 Agent 可能运行命令、生成代码、读写文件。Sandbox 用来隔离宿主机，防止误删文件、读取密钥、访问不该访问的网络或系统资源。

## 6. Memory 和 RAG 有什么区别？

Memory 是 Agent 跨会话沉淀和复用的长期知识，DeepAgents 里偏 filesystem-backed。RAG 是从外部知识库检索资料。两者可以结合。

## 7. Subagent 什么时候用？

当任务可以拆成多个独立分支，或需要不同角色专业化处理时使用。比如日志分析、DB 查询、代码分析、报告生成。

## 8. Tool 怎么设计才安全？

默认只读，参数类型明确，返回结构化证据，有超时、限流、审计和错误处理。写操作或生产影响操作必须审批或禁止。

## 9. Agent 结果怎么证明可信？

必须输出证据链：工具名称、查询参数、时间范围、日志片段、SQL、代码路径、证据 ID。没有证据的结论不能标记 verified。

## 10. 生产最大风险是什么？

权限过大、无 sandbox、无 trace、无 eval、无限循环、成本失控、memory 污染、prompt injection、证据不足却强行下结论。

## 11. 怎么控制成本？

限制最大步骤数、子 Agent 数量、工具返回条数、输出大小；大结果写文件，只传摘要；缓存查询；弱模型处理低风险步骤，强模型做最终综合。

## 12. DeepAgents 适合替代 Codex 吗？

不建议直接替代。更适合在 Codex 工作流中作为一个可控子系统，负责长任务分析、核实和报告生成。
