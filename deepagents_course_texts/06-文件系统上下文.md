# 06｜文件系统上下文

## 本讲目标

长任务中，大结果应该落文件，小摘要进入上下文。

## 核心内容

- 日志、SQL 结果、grep 命中、长代码片段都适合写文件。
- 最终报告应该引用证据文件，而不是只写自然语言结论。
- 每个 verified claim 都应能反查 evidence_id。


## 示例 / 模板

```markdown
# Evidence Index

| ID | Type | Source | Query/Path | Supports | Confidence |
|---|---|---|---|---|---|
| E001 | log | loki | service=order-api timeout | timeout spike | high |
```

## 工程注意点

- 不要只追求 demo 跑通，要关注权限、证据、失败处理和可复盘。
- 所有真实日志、数据库、shell 命令都应先通过 mock 或 sandbox 验证。
- 输出尽量结构化，方便 Codex 后续读取和整理。

## 面试回答

> 文件系统上下文降低 token 成本，提高复盘能力，也让 Codex 后续能直接读取中间产物和最终报告。

## 本讲练习

把本讲能力应用到“排查记录核实 Agent”里，写出你会暴露给 Agent 的工具、路径权限和输出字段。
